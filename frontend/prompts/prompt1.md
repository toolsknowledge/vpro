# Master Prompt: Generate BRD and SRD for VPro Skills

Act as a professional Business Analyst and Software Requirements Engineer.

## Project Context

I want to develop a professional, responsive sample web page for my education technology company, **VPro Skills**.

The purpose of this web page is to display information about our upcoming training batches and help interested students explore available courses.

Example courses:
- Forward Deployed Engineer (FDE)
- Agentic AI
- Generative AI
- Other relevant technical training batches

## Your Task

Prepare two separate, professional documents:

### 1. Business Requirements Document (BRD)

Create a BRD that explains the business requirements of the VPro Skills upcoming batches web page.

Include only the following sections:

1. Project Overview
2. Business Objectives
3. Business Problem
4. Project Scope
5. Target Users
6. Business Requirements
7. Key Features
8. Business Benefits
9. Assumptions and Constraints
10. Success Criteria

Explain each section in simple, clear, friendly English.

Focus on what the business needs and why the web page is required.

### 2. Software Requirements Document (SRD)

Create an SRD based on the approved BRD.

Include only the following sections:

1. Project Overview
2. Functional Requirements
3. Non-Functional Requirements
4. User Interface Requirements
5. Course and Batch Information Requirements
6. Navigation Requirements
7. Responsive Design Requirements
8. Error Handling Requirements
9. Technical Constraints
10. Acceptance Criteria

Describe what the web page must do and how it should behave from a software perspective.

## Web Page Requirements

The sample web page should:

- Display the VPro Skills company name.
- Present upcoming training batches clearly.
- Include courses such as FDE, Agentic AI, and Generative AI.
- Display relevant batch information in an organized format.
- Use professional course cards or similar layouts.
- Provide a clear way for users to explore course and batch details.
- Use a clean, modern, professional, and responsive design.
- Work properly on desktop, tablet, and mobile screens.
- Use sample data for courses and batches.
- Keep the implementation simple and suitable for a demonstration.

## Documentation Rules

- Use simple English and friendly language.
- Maintain a professional business-document style.
- Use clear headings, numbered sections, bullet points, and tables wherever appropriate.
- Keep requirements specific, understandable, and testable.
- Assign unique IDs to individual requirements, such as BR-001 for business requirements and SR-001 for software requirements.
- Ensure the SRD is consistent with the BRD.
- Do not duplicate information unnecessarily.
- Do not invent company details, course fees, schedules, dates, eligibility criteria, contact information, or business policies.
- If any information is missing, explicitly mark it as **TBD (To Be Decided)** instead of making assumptions.
- Do not introduce unrelated features such as student login, payment gateways, an LMS, assessments, or backend integrations unless explicitly required.
- Do not add unnecessary sections, features, or technical complexity.

## Expected Output

Generate two separate, complete documents:

1. `VPro_Skills_BRD.md`
2. `VPro_Skills_SRD.md`

Both documents must be ready for professional review and suitable for use as project documentation before developing the sample web page.

Before finalizing, verify that:
- The BRD focuses on business needs.
- The SRD focuses on software requirements.
- Both documents describe the same project scope.
- Every requirement is relevant to the VPro Skills upcoming batches web page.
- No unsupported information or unnecessary features have been added.
